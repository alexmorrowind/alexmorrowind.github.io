# B1Pay × Octo — пакет для партнёрского обсуждения

Пакет подготовлен для первичного обсуждения B1Pay с Octo и другими лицензированными финансовыми партнёрами в Узбекистане.

## Что внутри

- `business_model.md` — бизнес-модель, роли, пользовательские сценарии, доходы, риски и дорожная карта.
- `architecture.md` — целевая схема платформы, API-контуры и потоки данных.
- `sources_and_assumptions.md` — источники, текущие факты по репозиторию и допущения для юридической/технической проверки.
- `assets/platform_architecture.svg` — редактируемая векторная схема платформы.
- `output/B1Pay_Octo_Partner_Proposal.pptx` — редактируемая презентация PowerPoint.
- `output/B1Pay_Octo_Partner_Proposal.pdf` — PDF-версия презентации.
- `output/B1Pay_Octo_One_Pager.pdf` — краткий одностраничный документ для отправки партнёру.

## Важное ограничение

Документы описывают партнёрскую модель и не утверждают, что B1Pay уже является банком, платёжной организацией, оператором платёжной системы, МФО, страховой организацией или лицензированным инвестиционным посредником. Любой регулируемый продукт должен запускаться только после юридического анализа, согласования роли каждого участника, получения необходимых разрешений/лицензий либо подключения лицензированного партнёра.

В презентации намеренно использованы формулировки «планируется», «через лицензированного партнёра», «подлежит согласованию» и «пилот», чтобы не создавать ложного обещания доступности банковских услуг.

## Как обновить файлы

Исходник генерации презентации находится в `src/generate_deck.py`. Для повторной сборки:

```bash
python3 -m pip install --user python-pptx reportlab
python3 deliverables/octo-business/src/generate_deck.py
```

После генерации `soffice` конвертирует PPTX в PDF (если он доступен в окружении). Схема SVG создаётся отдельным скриптом `src/generate_architecture.py`.

## Что проверить перед отправкой Octo

1. Название юридического лица B1Pay и контактное лицо.
2. Какие именно продукты Octo разрешает подключать: P2P, payout, acquiring, card-to-card, KYC, settlement.
3. Территории, лимиты, комиссии, SLA, chargeback/dispute flow и требования к AML/KYC.
4. Юридическую структуру B1Pay и необходимость отдельной регистрации/лицензии.
5. Договоры с банками, МФО, страховыми организациями и инвестиционными партнёрами.
6. Согласованные домены, redirect/webhook URL, IP allowlist и тестовые реквизиты.
